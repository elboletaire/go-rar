# go-rar: RAR4 store-only archives, archive/zip style

Pure Go (no cgo, stdlib only) library, package `rar`, module
`github.com/elboletaire/go-rar`, MIT. First consumer: manga-downloader packing
CBR files, so the API mirrors `archive/zip` closely enough that swapping
`zip.NewWriter` for `rar.NewWriter` just works.

- Phase 1: Writer (this goal).
- Phase 2: Reader.

## Why RAR4 and store-only

junrar (Java, used by Tachiyomi forks, Komga and many Android readers) cannot read
RAR5; every RAR5 reader also reads RAR4. CBR pages are JPEG/PNG/WebP/AVIF, already
compressed, so LZ compression gains nothing; store-only is also the part that is
fully documented and stays clear of the unrar license, which forbids recreating
the RAR compressor. Implement from the RAR 2.9-4.x technote only; never consult
unrar source. libarchive (BSD) may be consulted.

Out of scope: compression, encryption, solid, multi-volume, comments, recovery
records, extended time, SFX, RAR5 writing.

## On-disk format (all integers little-endian)

Every block starts with a 7-byte base header:

| field     | size | notes                                                       |
|-----------|------|-------------------------------------------------------------|
| HEAD_CRC  | 2    | low 16 bits of CRC32 (IEEE) over HEAD_TYPE..end of header   |
| HEAD_TYPE | 1    |                                                             |
| HEAD_FLAGS| 2    |                                                             |
| HEAD_SIZE | 2    | full header size including these 7 bytes                    |

Archive layout: marker, main header, (file header + data)*, end block.

1. Marker: exactly `52 61 72 21 1A 07 00` ("Rar!\x1a\x07\x00").
2. Main header: TYPE `0x73`, FLAGS `0x0000`, SIZE 13, then RESERVED1 (2 zero
   bytes) and RESERVED2 (4 zero bytes). CRC over the 11 bytes after HEAD_CRC.
3. File header, TYPE `0x74`, SIZE = 32 + (8 if LARGE) + NAME_SIZE:

   | field          | size | value                                              |
   |----------------|------|----------------------------------------------------|
   | PACK_SIZE      | 4    | low 32 bits of data size                           |
   | UNP_SIZE       | 4    | low 32 bits of data size                           |
   | HOST_OS        | 1    | 2 (Win32)                                          |
   | FILE_CRC       | 4    | CRC32 (IEEE) of the data; 0 for directories        |
   | FTIME          | 4    | DOS date/time of Modified                          |
   | UNP_VER        | 1    | 29                                                 |
   | METHOD         | 1    | 0x30 (store)                                       |
   | NAME_SIZE      | 2    | byte length of FILE_NAME                           |
   | ATTR           | 4    | Win32 attributes (see below)                       |
   | HIGH_PACK_SIZE | 4    | only if LARGE: high 32 bits of data size           |
   | HIGH_UNP_SIZE  | 4    | only if LARGE: high 32 bits of data size           |
   | FILE_NAME      | n    | see "File names"                                   |

   FLAGS: `0x8000` always (PACK_SIZE acts as ADD_SIZE), `0x0100` LARGE when the
   size exceeds 0xFFFFFFFF, `0x0200` UNICODE when the name is not pure ASCII,
   `0x00E0` for directories (dictionary bits all set means "directory").
   The header is followed by the raw data (PACK_SIZE + HIGH_PACK_SIZE<<32 bytes).
4. End block: TYPE `0x7B`, FLAGS `0x4000`, SIZE 7. Its bytes must come out as
   `C4 3D 7B 00 40 07 00` (good self-check for the CRC code).

### Paths and attributes

- API names use `/`; on disk the separator is `\` (Win32 host). Directory
  entries are given with a trailing `/` in the API (like zip) and stored without
  any trailing separator. A leading `/` is stripped, as zip does.
- ATTR for Win32 host: directories `0x10`; files `0x20` (archive); add `0x01`
  (read-only) when the mode has no write bits.
- `Mode()` from ATTR: HostOS 0/2 (DOS/Win32): dir → `fs.ModeDir|0777`, file →
  `0666`, read-only clears write bits. HostOS 3 (Unix): ATTR is a Unix `st_mode`;
  map type bits (dir, symlink, etc.) and permission bits like zip's
  `unixModeToFileMode`.

### DOS time

`(year-1980)<<25 | month<<21 | day<<16 | hour<<11 | minute<<5 | second/2`, taken
in the time's own location (as archive/zip does). Times before 1980-01-01 clamp to
1980-01-01 00:00:00; zero time means 1980-01-01 too.

### File names

- Pure ASCII names: FILE_NAME is the name bytes, no UNICODE flag.
- Otherwise set UNICODE and write: the name's UTF-8 bytes (fallback for readers
  that ignore Unicode; must contain no 0 byte), a `0x00` byte, then RAR's
  encoded UTF-16 name:
  - Byte `HIGH` (we always write `0x00`).
  - Then groups: a flag byte holding four 2-bit opcodes, most significant pair
    first, followed by the data for those (up to) four characters. Opcodes:
    `0` = 1 byte, char = byte; `1` = 1 byte, char = HIGH<<8|byte; `2` = 2 bytes,
    char = lo | hi<<8; `3` = run copied from the ASCII part (decoder only).
  - The encoder emits opcode 0 for UTF-16 units < 0x100 and opcode 2 otherwise.
    Unused opcode slots in the last flag byte are left 0; decoders stop when the
    encoded bytes run out.
  - Runes above U+FFFF become UTF-16 surrogate pairs (two units).
- Decoding (phase 2) must implement all four opcodes. For opcode 3, read a byte
  L: if `L&0x80`, read correction byte C and emit `(L&0x7F)+2` chars
  `((ascii[pos]+C)&0xFF) | HIGH<<8`; else emit `L+2` chars `ascii[pos]`; `pos`
  is the current output position. If UNICODE is set but there is no 0 byte, the
  name is UTF-8.

## API

```go
const Store uint8 = 0x30

var (
    ErrFormat       = errors.New("rar: not a valid rar file")
    ErrAlgorithm    = errors.New("rar: unsupported compression algorithm")
    ErrChecksum     = errors.New("rar: checksum error")
    ErrUnsupported  = errors.New("rar: unsupported archive feature")
    ErrInsecurePath = errors.New("rar: insecure file path")
)

type FileHeader struct {
    Name         string    // "/"-separated; trailing "/" marks a directory
    Modified     time.Time
    CRC32        uint32
    PackedSize   uint64
    UnpackedSize uint64
    Method       uint8
    HostOS       uint8     // 0 MS-DOS, 2 Win32, 3 Unix
    Attributes   uint32
    Flags        uint16
}
func FileInfoHeader(fi fs.FileInfo) (*FileHeader, error)
func (h *FileHeader) FileInfo() fs.FileInfo
func (h *FileHeader) Mode() fs.FileMode
func (h *FileHeader) SetMode(mode fs.FileMode)   // sets Win32 attrs, HostOS = 2

// Phase 1
type Writer struct{ /* unexported */ }
func NewWriter(w io.Writer) *Writer
func (w *Writer) Create(name string) (io.Writer, error)
func (w *Writer) CreateHeader(fh *FileHeader) (io.Writer, error)
func (w *Writer) AddFS(fsys fs.FS) error
func (w *Writer) Close() error

// Phase 2
type Reader struct{ File []*File }
func NewReader(r io.ReaderAt, size int64) (*Reader, error)
func (r *Reader) Open(name string) (fs.File, error)
type ReadCloser struct{ Reader /* + file */ }
func OpenReader(name string) (*ReadCloser, error)
func (rc *ReadCloser) Close() error
type File struct{ FileHeader /* unexported */ }
func (f *File) Open() (io.ReadCloser, error)
func (f *File) DataOffset() (int64, error)
```

### Writer behaviour

- The marker and main header are written lazily, on the first Create/Close, so
  `NewWriter` never fails and an archive with no entries is still valid
  (marker + main + end).
- `Create(name)` = `CreateHeader(&FileHeader{Name: name, Modified: time.Now()})`.
- `CreateHeader` finishes the previous entry (writes its header then its data)
  and returns a writer that buffers this entry in memory. Size and CRC32 fields
  from the caller are ignored and computed. Method must be 0 or Store, else
  `ErrAlgorithm`. Attributes: if the caller set neither Attributes nor a mode,
  use the defaults above. Directory entries return a writer that errors on any
  non-empty Write.
- Writing to a returned writer after the next Create/Close returns an error, as
  does any call after Close. Close writes the pending entry and the end block; it
  does not close the underlying writer.
- `AddFS` walks `fsys` in lexical order, adding directories (with `/`) and
  regular files, using `FileInfoHeader`; other file types are an error.
- Names: empty names and names containing a 0 byte are rejected.

### Reader behaviour (phase 2)

- Verify the marker; the RAR5 marker (`Rar!\x1a\x07\x01\x00`) → `ErrUnsupported`.
- Verify each header's CRC16 (`ErrFormat` on mismatch); skip unknown block types
  via HEAD_SIZE plus ADD_SIZE (4 bytes after the base header, present when
  `FLAGS&0x8000`).
- Main header volume/solid/encrypted-headers flags (`0x0001`, `0x0008`,
  `0x0080`) → `ErrUnsupported`. Split-file flags (`0x01`, `0x02`) or the
  encrypted flag (`0x04`) on a file header → `ErrUnsupported` when opening it.
- Listing works for any method; `File.Open` on method other than Store returns
  `ErrAlgorithm`; reading to EOF verifies CRC32 (`ErrChecksum`).
- Convert `\` to `/` for HostOS 0 and 2; directories get a trailing `/`.
- Like zip: if any name is not `filepath.IsLocal` or contains `\` after
  conversion, return the reader together with `ErrInsecurePath`.
- `Reader.Open` implements `fs.FS` (synthesising implied directories, like zip).
- No panics or unbounded allocation on hostile input: sizes are checked against
  the archive size before allocating.

## Testing

- Golden bytes: empty archive, end block, one small ASCII file.
- Unit tests: DOS time, name encoding (ASCII, Latin-1, CJK, emoji/surrogates),
  attributes/Mode round trip, LARGE flag header encoding (header only, without
  writing 4 GiB), error paths.
- Oracle tests (skip when the tool isn't on PATH): archives written by the
  Writer must pass `7z t`, list the right names and sizes in `7z l -slt`,
  extract byte-identical with `7z x` and with `bsdtar -xf`, including names like
  `Ñandú/ページ 01.jpg` and `😀.png`, nested directories and an empty file.
- Phase 2: round trip Writer → Reader, oracle comparisons, and a `FuzzReader`
  fuzz target seeded with writer output.
